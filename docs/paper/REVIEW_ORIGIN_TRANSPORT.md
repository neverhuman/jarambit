# Review-origin transport and eligibility protocol

This protocol describes prospective operator work. It does not attest that an
account or runtime is eligible, that a review was submitted, or that controls
passed. Source authors, including the guard and protocol authors, cannot supply
this change's final independent review. Root owns the real assignment, freeze,
policy pins, acceptance and delivery; the designated independent reviewer owns
its actual observations and submission.

## Approved transport and truthful command evidence

Preserve the complete actual outer argv in the submission, origin and authentic
tool record. The approved wrapper is the exact absolute executable
`/home/ubuntu/.local/bin/gh-role`, literal `reviewer`, zero or one
`--ack-unassociated` immediately before literal `api`, exactly one expected
`repos/OWNER/REPO/pulls/NUMBER/reviews` endpoint, one explicit `--method POST`
(or `-X POST`) and one `--input` nonflag path. Only the existing optional
`rtk proxy` prefix is accepted. Unknown programs, roles, wrapper switches,
duplicate flags and unconsumed API arguments are refused. The existing direct-gh
parser remains supported; this does not authorize bypassing role routing.

The observed public helper SHA256 is
`2b60b96fb00de7d50cc2ea43cf1f8d97bcd6b8aa239b7a1ebf426451a68e04c9`.
Root must bind the actual approved helper path/hash and authentic preflight
records to the final trusted evidence; a changed helper requires fresh review.
Do not inspect token/config files, change authentication, or infer an observed
child argv from helper source. An internal parser view is derived validation,
not a replacement for the recorded outer command.

**The helper classifies the JSON `--input` route as `kind=other`; its
`check_eligible` approval branch does not run.** Credential routing and account
validation do not establish approval independence. The acknowledgement records
provenance already resolved; it is not an eligibility check or override.

## Required read-only evidence before any POST

The following are reference commands with placeholders, not executed proof.
Run them only in the genuinely assigned independent runtime through approved
role routing, retaining exact argv, exit, raw response/status/header/tool records
and their hashes. No credential or environment capture is needed.

rtk proxy /home/ubuntu/.local/bin/gh-role reviewer api repos/OWNER/REPO

rtk proxy /home/ubuntu/.local/bin/gh-role reviewer api repos/OWNER/REPO/pulls/NUMBER

## Submission and later guard verification

Only after all gates actually pass may the designated eligible runtime submit
once with the approved wrapper and a structured request file containing explicit
`event: APPROVE`, exact `commit_id` and the required provenance body. Preserve
request bytes/hash, complete actual outer argv, actual exit and response bytes,
review ID, account, state, full commit, time, URL and body. Root separately pins
the authentic observed submission-origin record. Fetch fresh actual review and
complete CI/policy JSON for verification; do not synthesize API evidence.

The guard's transport acceptance proves neither account eligibility nor that the
helper called `check_eligible`. Keep the external evidence and that limitation
explicit. An inferred helper child argv or fabricated helper decision/audit field
cannot replace actual tool evidence. Historical operator gaps remain historical;
this protocol cannot create retroactive approval provenance.
